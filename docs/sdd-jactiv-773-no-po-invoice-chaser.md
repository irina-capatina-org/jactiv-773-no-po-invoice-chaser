## 1. API Workflow Overview

The No-PO Invoice Chaser is an unattended API Workflow that runs weekday mornings (10:00 Romania time, EET/EEST) to enforce the no-PO-no-pay policy (BR-01). It queries Coupa for invoices without properly linked purchase orders (BR-04: status draft/new, past 7 days only), counts qualifying records, and notifies the AP SME on Slack with a summary and filtered invoice list (BR-06). On clean days (zero qualifying invoices), it sends nothing per BR-07. The count alone is reported; individual invoices are not listed (BR-05). The automation creates no records and makes no changes to Coupa (BR-10).

**Trigger:** Orchestrator schedule, weekday 10:00 Romania time (org architectural considerations §1, §5)

**Outcome:** One Slack direct message to member ID WLX9BD8FN if qualifying_count > 0; no message if count = 0; workflow output contains status, qualifying_count and slack_sent flag.

## 6. Error Handling

The PDD specifies no retry, no fallback, and no error recovery (BR-08, BR-09). A run that cannot complete is recorded as failed; no Slack message is sent.

| Failure | Trigger | Detection | Action |
|---|---|---|---|
| Coupa unavailable | Login or query fails at step 6 (HTTP_Request_Coupa) | HTTP error status or exception | Catch at workflow boundary; log error; terminate with failed status; output not sent |
| Slack delivery failure | Step 14 (HTTP_Request_Slack) returns non-200 or ok ≠ true | HTTP error or response.ok = false in step 15 script | Catch at workflow boundary; log Slack error; terminate with failed status |
| Network timeout | HTTP request timeout at Coupa or Slack | HTTP timeout exception | Catch at workflow boundary; log timeout; terminate with failed status |
| Credential expiry | Credential asset is empty or expired | Integration Service returns auth error during connector call | Catch at workflow boundary; log credential error; terminate with failed status |
| Unhandled exception | Unexpected error anywhere | Exception not caught by above | Workflow Try/Catch at top level (single boundary per org considerations §8); log full exception; terminate with failed status |

No notification is sent in any error case. All errors are logged to Orchestrator job logs (org considerations §7).

## 8. Testing Strategy

### Happy Path

| Test case | Input | Expected result | Assert |
|---|---|---|---|
| Clean run, qualifying invoices present | Schedule trigger on weekday 10:00 (or manual trigger) | qualifyingCount > 0; Slack DM posted to WLX9BD8FN | Response status = "Successful", slack_sent = true, qualifying_count matches manual count |
| Clean run, no qualifying invoices | Schedule trigger on clean day (all invoices have POs) | qualifyingCount = 0; no Slack DM sent per BR-07 | Response status = "Successful", slack_sent = false, qualifying_count = 0 |
| Window boundaries | Run on Monday for Friday invoices (past 7 days) | Coupa query filters correctly by date window | Returned invoices all within [today−7 .. today] |
| Date arithmetic | Run on different weekdays | windowStart and windowEnd calculated correctly for each day | windowStart = 7 days prior; windowEnd = today; both YYYY-MM-DD format |

### Business Exceptions

| ID | Scenario | Trigger | Expected result | Assert |
|---|---|---|---|---|
| B1 | Credit note encountered | Invoice with invoice-type = "Credit Note" | Excluded from count; logged to exclusionLog | qualifyingCount does not include credit notes; log entry present |
| B2 | Description-only PO | Invoice with PO text in description but no line-level po-number/order-header-num | Treated as no linked PO; included in qualifyingCount if all other rules pass | Invoice appears in qualifying count; BR-02 compliance verified |
| B3 | No qualifying invoices (clean day) | Coupa returns invoices but all have linked POs or are credit notes | Count = 0; no Slack DM sent per BR-07 | Response status = "Successful", slack_sent = false, qualifying_count = 0 |

### System Errors

| ID | Scenario | Trigger | Expected result | Assert |
|---|---|---|---|---|
| S1 | Coupa unavailable | Coupa query fails with HTTP error at step 6 | Workflow terminates with failed status; no Slack sent; error logged | Job log contains HTTP error; qualifying_count not set; run marked failed |
| S2 | Coupa element not found | Coupa response missing expected fields | Response parsing fails; exception caught | Job log documents missing field; run marked failed |
| S3 | Slack delivery failure | Slack request fails or returns ok ≠ true | HTTP error from Slack API; Javascript_ValidateSlack throws | Job log contains Slack error; run marked failed; no retry per BR-08 |
| S4 | Network timeout | HTTP request to Coupa or Slack exceeds timeout | HTTP timeout exception during connector call | Job log contains timeout error; run marked failed; no retry per BR-08 |
| S5 | Credential expiry | Credential asset expired or missing | Integration Service auth error during HTTP activity | Job log contains credential error; run marked failed per BR-08 |
| S6 | Unhandled exception | Unexpected error anywhere in workflow | Exception not caught by specific handlers | Workflow-level Try/Catch; log full exception; run marked failed per BR-08 |
